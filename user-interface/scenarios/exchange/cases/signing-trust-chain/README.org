#+TITLE: Exchange Signing Trust Chain

* Case layout

This directory owns the vertical incident comparison. =reasoning.ss= and
=hypotheses.ss= hold bounded Ascent candidate rules, =query.ss= holds the GQL
selection contracts, =simulation.ss= holds synthetic POO revisions, and
[[file:proof/tla/SigningIntentBoundary.tla][proof/tla/SigningIntentBoundary.tla]] holds the pre-signing threat model.
The sibling [[file:proof/cedar/README.org][proof/cedar/]] directory contains the Cedar policies generated by
this Case's Lean-POO model. The Lean source lives in [[file:proof/lean/README.org][proof/lean/]]; its pinned cedar-poo-spec
dependency supplies the generic proof and Rust export libraries. This Case
owns both the source and the published policies that its downstream
authorization flow can consume. A generated policy is a
model artifact, not evidence about either incident.

* Structural risk scope

The shared risk is *instruction contamination before a valid signature*:
the signing authority may receive bytes that differ from the transaction
authorized by the legitimate decision makers. A cryptographic signature can
then be valid while the transfer is unauthorized. This risk is defined by the
trust boundary, not by a particular wallet product or intrusion route.

| Incident or model | Entry surface | What is established here | What remains a hypothesis |
|-------------------+---------------+--------------------------+---------------------------|
| Bybit 2025 | Human signing interface | Bybit reports a compromised Safe developer account and deceptive signing interface. | The generic model does not reconstruct every production control. |
| Bitget 2026 | Exchange hot/warm-wallet pipeline | Bitget reports unauthorized outflow; the CEO's preliminary backend explanation is reported separately. | Record mutation, API replay, queue injection, destination mapping, exact signer ingress. |
| Shared threat model | Candidate transaction before signing | Either entry class can be represented as a candidate that lacks an independently bound intent or display witness. | No particular candidate path is thereby proven to have occurred. |

The defensive cut is an independently authenticated, signer-side binding of
decoded transaction bytes to user intent, risk approval, ledger reservation,
display confirmation where applicable, wallet epoch, and a one-use nonce.
Cedar evaluates the bound request; the Host checks provenance and applies
the signing effect. The [[file:proof/tla/SigningIntentBoundary.tla][TLA+ model]] examines the temporal cut,
[[file:hypotheses.ss][Ascent]] compares possible ingress explanations, and
[[file:proof/lean/README.org][Lean-POO/Cedar]] replays policy revisions and a symbolic signing Host.
Their outputs have separate authority: a candidate route cannot authorize
a transfer, and a Cedar permit cannot authenticate a witness producer.

The dotted links are candidate mechanisms, not established Bitget attack
steps. A bounded Ascent closure can show whether the Case's supplied edges
contain a route from a suspected surface to the transfer. The output is
explicitly non-authoritative. The [[file:query.ss][GQL query contract]] constructs a
language-owned AST for selecting event links and source metadata from an
admitted ontology graph. The atomic test checks its projection and Query
admission; it does not execute GQL or bind query results. MRR and the Host
must perform those steps with admitted evidence before the selected links
can become observed Case facts. Neither graph reachability nor a GQL path
proves that a route happened.

The Scheme Ascent kernel and its rule qualifications are maintained by
[[https://github.com/tao3k/gerbil-ascent][gerbil-ascent]]. POO Flow PR #34 pins that package. The
[[file:reasoning.ss][Exchange Case rules]] use Ascent to compute both possible routes (observed and
proposed links) and routes supported only by observed links. The Lambda
package declares no Ascent dependency of its own; its CI consumes the pinned
POO Flow checkout. MRR owns semantic source identity, lineage, and admission;
this Scenario does not assert an MRR admission receipt.

| Discriminator | Backend substitution | Interface substitution |
|---------------+----------------------+------------------------|
| Payload before signer ingress differs from user intent | Supports this route | Does not distinguish alone |
| Signed bytes differ from independently captured displayed bytes | Possible downstream symptom | Supports this route |
| Signer accepted a request without an independent intent attestation | Exposes shared trust boundary | Exposes shared trust boundary |
| Complete signer ingress log absent | Route remains uncertain | Route remains uncertain |
| All matching records originate from the same backend | Correlated, weak support | Correlated, weak support |

These are *tests to discriminate hypotheses*. They do not claim that any listed
artifact has been recovered from either incident. Independent signer ingress,
approval display capture, chain transaction bytes, and timestamped source
identities are needed before a forensic conclusion.

The [[file:../../../../../t/ontology/exchange-signing-reasoning-test.ss][atomic Case test]] runs under the POO Flow Observability test boundary. It
uses a Bitget notice as one observed transfer link and
marks the backend, queue, and signer links as proposed. Ascent derives a
possible backend-to-outflow route but no fully observed route. Removing the
queue link removes the possible route. These expectations test the model's
epistemic separation, not Bitget's actual intrusion path.

* Synthetic attack-chain replay

[[file:simulation.ss][The replay]] represents successive snapshots as POO extensions of one
observed terminal transfer. The backend branch adds a substituted payload,
queue message, signer ingress, and signing effect. An alternative interface
branch represents the same signer-intent boundary through a changed display.
It is inspired by the separately disclosed Bybit incident; it is not a
Bitget observation. Each stage is evaluated separately through the bounded
Ascent API, so one failed or expensive stage cannot silently turn a
candidate route into an admitted fact.

| Snapshot | Publicly observed link | Added synthetic links | Ascent candidate |
|----------+------------------------+-----------------------+------------------|
| Public notice | Unauthorized transfer | None | None |
| Record substitution | Same terminal link | Backend to payload | None |
| Queue injection | Same terminal link | Payload to queue | None |
| Signer ingress | Same terminal link | Queue to signer | None |
| Candidate transfer | Same terminal link | Signer to transfer | Backend to outflow, proposed only |
| Queue interrupted | Same terminal link | Queue input removed | None |
| Interface substitution | Same terminal link | Interface to display to signer to transfer | Interface to outflow, proposed only |

The queue cut is a structural counterfactual, not evidence that an actual
queue was interrupted. The interface branch uses the same terminal node to
compare mechanisms; that graph join must not be read as evidence that the
Bybit interface compromise occurred at Bitget.

* Competing ingress hypotheses

[[file:hypotheses.ss][The hypothesis Case]] uses Ascent rules to join admitted and provisional
signals with five candidate mechanisms. The [[file:query.ss][GQL signal query]] is a
language-owned AST selecting signal identity, evidence source, and admission
status. Its test verifies Query admission but does not execute GQL. MRR and
the Host must bind an actual, complete query receipt before supplying any
independently authenticated signal to Ascent. The public transfer notice
supports every candidate equally; it does not identify the ingress route.

| Candidate mechanism | Assumed attacker control | Distinguishing signal to seek | Independent challenge | Signing boundary that cuts it |
|---------------------+--------------------------+-------------------------------+-----------------------+------------------------------|
| Withdrawal record mutation | Write to a withdrawal record before signing | Record without matching authenticated user intent | Exact earlier user intent receipt | Intent owner attests the decoded bytes |
| Internal API replay | Invoke or replay a signer request | Duplicate request identity or nonce | One-use request ledger | Atomic one-use signer gate |
| Queue injection | Submit a message outside the authorized producer path | Orphan message in signer-owned ingress log | Verified producer chain | Signer verifies admission and producer receipt |
| Address-map substitution | Change destination mapping during construction | User destination differs from signer-decoded destination | Independently matched destination | Signer decodes and binds exact bytes |
| Interface substitution | Change what a human approver sees | Trusted display differs from signed bytes | Trusted rendering matches bytes | Independent display and byte comparison |

The three backend variants above also have separate candidate topologies in
[[file:simulation.ss][the replay]]. These are adversary-capability models, not claims about
Bitget's implementation. An observation from a backend-controlled log is
provisional even if it matches a prediction. A separately admitted signer
record can narrow the queue hypothesis; a contradictory producer record must
remain visible. Neither a single matching signal nor a path in the graph
confirms an intrusion mechanism. The atomic tests demonstrate all three
outcomes without promoting a hypothesis to a fact or permit.

* Fixture consequence reasoning

[[file:outcome.ss][The POO outcome algebra]] accepts Case-owned event rows through a =semantics=
slot. Its Ascent rules count a direct loss only when changed intent bytes,
a matching signature, and an independently observed outflow join on the
same transaction. For an administrative signing path, it also requires an
observed wallet-control change, ordering evidence, and a later linked drain.
A valid signature or public aggregate alone does not establish this chain.

| Synthetic branch | Supplied linked outflows | Derived fixture total | Missing-evidence counterexample |
|------------------+--------------------------+-----------------------+---------------------------------|
| Direct transfer | USD 30,000 + USD 45,000 | USD 75,000 | Removing the signature yields zero. |
| Administrative change then drain | USD 120,000 | USD 120,000 | Removing the observed control change yields zero. |

These are intentionally synthetic figures, separate from both exchanges'
reported losses. The [[file:../../../../../t/ontology/exchange-signing-outcome-test.ss][atomic outcome test]] checks the joins and missing-evidence
cases. An application must bind independent chain, signer, and ordering
receipts before these rows can support an incident conclusion.

* Pre-signing temporal threat model

[[file:proof/tla/SigningIntentBoundary.tla][SigningIntentBoundary.tla]] lifts the two known structural entry classes
above any single wallet implementation. The model has a prepared candidate,
independent intent/risk/ledger witnesses, a signer-side display comparison,
a one-use nonce, a freeze flag, a symbolic signing step, and a symbolic
broadcast step. Backend compromise makes a candidate acceptable to the weak
pipeline without independent witnesses; interface compromise makes the
display disagree with the bytes. =WeakSign= relies on the pipeline's
candidate flag; =BoundSign= requires the independent witnesses and exact
display match.

#+begin_src mermaid
stateDiagram-v2
  [*] --> Prepared: legitimate or synthetic entry
  Prepared --> Signed: WeakSign on candidate flag
  Prepared --> Signed: BoundSign on independent witnesses
  Signed --> Broadcast: no freeze
  Prepared --> Frozen: emergency freeze
  Signed --> Frozen: emergency freeze before broadcast
#+end_src

| TLA+ predicate | Intended meaning | Executable companion |
|----------------+------------------+----------------------|
| =NoUnboundSign= | A signed candidate has independent witnesses and a matching signer display. | Lean Host rejects the shared-source attempt. |
| =NoUnboundBroadcast= | Broadcast never follows an unbound signature. | Lean weak Host exposes a violating synthetic effect. |
| =SignedNonceConsumed= | Signing consumes one request nonce. | Lean Host rejects the second use. |

=AttackSpec= permits =WeakSign= and therefore has a candidate path that
violates the first two predicates. =DefendedSpec= substitutes =BoundSign=.
The atomic Gerbil test checks parser-owned syntax, source identity, and exact
roundtrip. It does *not* run TLC or prove temporal invariants. The separate
Lean replay proves only its finite symbolic Host cases; no machine-checked
TLA+/Lean refinement is claimed.

* Authorization boundary

The [[file:proof/lean/README.org][Lean-POO Exchange model]] composes intent, risk, ledger, signer,
incident freeze, and recovery policies and exports complete =.cedar= files
through Rust into [[file:proof/cedar/README.org][this Case's proof/cedar/]]. Cedar evaluates an admitted
request. The signer Host must bind
the exact payload bytes, chain, destination, amount, nonce, wallet epoch, and
independent attestations to that request, then apply an atomic effect gate.
If all claims come from one compromised backend, matching fields can still
pass a policy; the example includes this counterexample. Ascent candidates
guide investigation and freeze scope but never become =permit= facts.
The Lean/Cedar replay then tests independent controls, common-source claim
contamination, incident freeze, and premature removal of the freeze. It
also models an abstract signer Host: if it accepts Cedar =Allow= while trusting
backend-supplied claims, the attacker bytes reach a modeled signing effect;
requiring separately authenticated intent, risk, ledger, and display
witnesses blocks the same attempt. The model signs no real bytes and submits
no wallet transaction.

* Scenario boundary

This directory carries the incident-specific source ledger, hypothesis
matrix, TLA+ model, and Lean-generated Cedar policy set. It contains no keys
or live exchange transactions. A downstream deployment must ingest its own
admitted records, check source independence, and replay the published Cedar
policy set through the POO Flow Host before any signer effect.
