The JSON files are retained byte-for-byte. Runtime source admission verifies
byte count and SHA-256 before representation parsing. JSON parse success does not
itself establish FHIR or AU Core conformance.

The lazy materializer parses the admitted byte vector directly with Gerbil
=std/text/json= =bytes->json-object=.  The generated XHTML under =text.div= is
only a JSON string: no XHTML/XML parser is invoked, and that narrative is not
retained in the materialized runtime artifact.

XML is intentionally not vendored because the upstream XML represents the same
canonical profile, version and constraint coverage.  A second representation is
admitted only when it contributes distinct required coverage.
