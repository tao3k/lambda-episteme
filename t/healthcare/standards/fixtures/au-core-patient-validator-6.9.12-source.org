* Reproduction

#+begin_src sh
java -jar validator_cli.jar \
  au-core-patient-valid.json \
  au-core-patient-data-absent.json \
  au-core-patient-invalid.json \
  au-core-patient-xor-conflict.json \
  -version 4.0.1 \
  -ig hl7.fhir.au.core#1.0.0 \
  -profile http://hl7.org.au/fhir/core/StructureDefinition/au-core-patient \
  -tx n/a \
  -output au-core-patient-validator-6.9.12-operation-outcomes.json
#+end_src

The output is a FHIR collection Bundle.  Entries retain the command input
order and each =entry.resource= is the Validator's unmodified
=OperationOutcome=.  The normal test path only imports this fixed evidence; it
does not download packages or execute Java.

The executable qualification entrypoint is:

#+begin_src sh
FHIR_VALIDATOR_JAR=/path/to/validator_cli.jar \
  just check-healthcare-fhir-reference-validator
#+end_src

It verifies the JAR digest, streams Validator progress, and compares the
complete decoded output Bundle.  The local FHIR package cache must already
contain the pinned package closure; package acquisition is not part of this
qualification gate.
