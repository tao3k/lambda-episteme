* Implemented boundary

The SDLC domain now declares explicit applicability modes for all 130 source
requirements: 19 conditional project rules, 81 unconditional project rules and
30 institutional rules. Unknown identifiers fail; new catalog rows cannot
silently inherit unconditional support. The generated
[[file:nasa-implementation-matrix.org][implementation matrix]] records 130/130
rule implementations while keeping module completion distinct from a project
compliance decision and NASA certification.

Native =poo-clos= classes constrain stage policies, lifecycle snapshots and
verification requests. =nasa-baseline-policy= selects all 100 project duties or
all 30 institutional duties in a separate policy scope. Custom stages expose
their selected requirements. Mixed project/institutional policies fail.

The core =contribution/verification= owns the only mutable issuance/revocation
state. The NASA factor owns source digest and domain snapshot projection.
Receipt presentation fields cannot grant authority: identity is checked against
private issuance state, with copied request snapshots and validity intervals.
Receipts are valid from issuance inclusive to expiry exclusive. Revocation,
cloning, altered presentation, changed artifact digest, changed source digest,
changed context and changed revision prevent admission.

Stage transitions recompute the entire policy prefix, so even a fabricated prior
stage label cannot bypass earlier requirements. Rebase starts at =unstarted= for
a new revision. Current failure evidence blocks advancement even with a verified
tailoring request. Tailoring first requires structurally complete matching
records, then a receipt from the configured authority verifier. The independent
UI example returns verification requests and accepts host-supplied receipts; it
contains no default approval callback.

* Limits that remain explicit

The NPR 7150.2D module implementation is complete across its 130 catalog rows,
conditions, criterion evidence, lifecycle admission, tailoring routing and
negative authority boundary. This does not claim that a project is compliant,
that NASA has certified it, or that every referenced external standard has been
implemented inside this contribution. External references are explicit
=declared-external-dependency= rows and remain a curated discovery index rather
than a recursive standards import.

A production verifier must read and authenticate actual artifact bytes, bind
reviewer competence and authority to the request, evaluate its source paragraphs
and referenced standards, and verify classification, scope and tailoring
signatures. The new adapter defines and tests this boundary; it does not provide
a production NASA identity service or signature backend. Unit/UI callbacks are
bounded test doubles. Trace and safety measurement evaluators exist separately;
the stage gate does not reconstruct their inventories from artifact digests.

Host configuration and clock are trusted. Receipts are local to one configured
adapter session and are not persistent or portable signatures. The issuance
boundary assumes serialized access. Verification must authorize the complete
requested interval and may depend only on snapshot-bound fields.

These checks do not establish a clean installed release, the entire parent POO
Flow suite, external runtime enforcement, or authorization to deploy/release.
